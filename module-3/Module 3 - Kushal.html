01 / 05 The Weapon

SYN Floods — Weaponising
the Handshake

In Module 1 you learned the TCP three-way handshake: SYN → SYN-ACK → ACK. It seems simple. But embedded in that ritual is a fundamental vulnerability that has been exploited for decades.

When a server receives a SYN packet, it must allocate memory immediately to track the half-open connection and wait for the ACK to complete the handshake. These pending connections live in a data structure called the TCP connection table — a finite resource. A typical server can hold between 10,000 and 64,000 half-open connections before the table fills up completely.

A SYN Flood exploits this by sending millions of SYN packets per second with spoofed (fake) source IP addresses. The server allocates memory for each one and sends SYN-ACK replies — to addresses that don't exist or never asked. The ACK never comes. Each entry in the connection table sits there, consuming memory, until it times out. With enough flood rate, the table fills faster than it drains, and the server can no longer accept any new legitimate connections. The website is effectively offline — not because the server crashed, but because it's waiting for responses from ghosts.

💡 Real-world analogy

Imagine a restaurant that can only seat 100 people. An attacker makes 100 reservations under fake names and never shows up. Real customers arrive — no tables. The restaurant isn't broken, the food isn't gone, the staff aren't sick. It simply cannot serve anyone because its capacity is consumed by phantom reservations it's still waiting to honour.

🔍 Why Spoofed IPs Make This Unstoppable Without Defence

Each SYN appears to come from a different, random IP address. A naive firewall that tries to block attacking IPs faces an impossible task — there are 4.3 billion possible IPv4 addresses. The defence cannot be "block the attacker's IP." It must be structural, targeting the pattern of the attack rather than its source.

02 / 05 The Multiplier

Amplification Attacks —
When 1 Byte Becomes 51,200

A SYN flood requires the attacker to generate all the traffic themselves. An amplification attack is far more efficient — it recruits the internet's own infrastructure as an unwilling weapon, multiplying the attacker's bandwidth by factors of hundreds or thousands.

The mechanics: certain internet protocols respond to a small request with a disproportionately large reply. An attacker sends a tiny request with a spoofed source IP — set to the victim's address. The internet service receives the request, generates a massive response, and sends it to the victim. The attacker never touches the victim directly. They just pull the trigger and let the internet's infrastructure deliver the payload. This is called reflection and amplification.

The most devastating example: Memcached amplification. Memcached is a distributed memory caching system. A single 15-byte UDP request to a misconfigured Memcached server returns up to 750KB — an amplification factor of 51,200x. The 2018 GitHub DDoS attack peaked at 1.35 Tbps using exactly this method — the largest DDoS attack ever recorded at the time.

📊 Real-World Scale

The 2016 Mirai botnet DDoS peaked at 1.2 Tbps using IoT devices. The 2018 GitHub attack hit 1.35 Tbps via Memcached — generated by a single attacker with ~1 Gbps upstream. In 2020, AWS mitigated a 2.3 Tbps attack. These weren't theoretical — they took real services offline for minutes to hours, costing millions of dollars in lost revenue per minute.

03 / 05 The Shields

Firewalls, IDS & IPS —
Building the First Line

A firewall is a policy enforcement point — a system that examines network traffic and decides, based on rules, whether to allow or block each packet. But not all firewalls are equal. The difference between a stateless and a stateful firewall determines whether your network survives a SYN flood.

Stateless Firewall

Also called: packet filter — examines each packet in isolation
📦
Examines each packet independently — source IP, destination IP, port, protocol flags only.
❌
No memory. Cannot tell whether a packet is part of an established connection or a new, unsolicited one.
⚠️
Rule: "Allow TCP port 80 inbound." This allows both legitimate requests and SYN flood packets — it can't tell the difference.
⚡
Extremely fast — no state to maintain. Good for high-throughput, low-complexity environments like core routers.
❌
Cannot detect SYN floods, port scans, or session hijacking — attacks that exploit connection state.

Stateful Firewall

Tracks the state of every active connection
🧠
Maintains a state table — a record of every active TCP connection (src IP, dst IP, port, sequence numbers, state).
✅
An ACK packet is only allowed through if a matching SYN was tracked. No state record? Packet dropped.
🛡
Can implement SYN cookies — a technique that avoids allocating server memory until the full handshake is verified.
✅
Detects and limits half-open connections per source IP, throttling SYN flood impact significantly.
⚠️
The state table itself can be exhausted by floods — the firewall must be sized appropriately and rate-limit SYNs.
IDS — Intrusion Detection System

The Alarm

Monitors traffic passively and alerts when suspicious patterns are detected

An IDS watches network traffic like a security camera — it sees everything but does nothing to stop it. When it detects a pattern matching a known attack signature (e.g. 10,000 SYN packets per second from random IPs to the same port), it generates an alert for a security analyst to investigate. Tools: Snort, Suricata, Zeek.

IPS — Intrusion Prevention System

The Bouncer

Monitors traffic inline and actively drops packets matching attack signatures

An IPS is an IDS placed inline — traffic must pass through it, not past it. When it detects an attack pattern, it doesn't just alert — it immediately drops the offending packets. The tradeoff: false positives can block legitimate traffic. IPS rules must be tuned carefully. Used in conjunction with stateful firewalls for layered defence.

SYN Cookies

The Memory Trick

A technique that avoids allocating server memory for half-open connections

Instead of storing half-open connection state in memory, the server encodes the connection info inside the SYN-ACK's sequence number. No memory allocated. When the ACK arrives, the server recomputes and verifies the cookie. If valid — legitimate connection, allocate memory. If never — no memory wasted. Completely negates SYN flood memory exhaustion.

Rate Limiting

The Throttle

Limiting the number of connections or packets accepted from any single source per second

A simple but highly effective first layer: "Accept no more than 10 new TCP connections per second from any single IP." Legitimate browsers rarely need more. An iptables rule using the hashlimit or connlimit module can enforce this in the kernel itself — before packets even reach the application. Effective even against distributed attacks when combined with geoblocking.

04 / 05 Network Architecture

VLANs & DMZ —
Dividing to Conquer

A firewall at the network perimeter is necessary but not sufficient. If an attacker gets past it — or if the threat originates inside your network — a flat, unsegmented network means everything is reachable from everywhere. One compromised device can reach every other device with no internal barriers.

Network segmentation solves this by dividing the network into isolated zones, each with its own trust level and access rules. Traffic between zones must pass through a firewall or router — it cannot flow freely. Two key tools: VLANs (Virtual Local Area Networks) for internal segmentation, and the DMZ (Demilitarised Zone) for separating public-facing services.

🏗 Why the DMZ is Non-Negotiable

Public-facing services must be reachable from the internet — that's unavoidable. The DMZ accepts this risk while containing it. If your web server is compromised, the attacker is trapped in the DMZ: they cannot initiate connections to the internal network (the internal firewall blocks inbound connections from the DMZ). The blast radius of a breach is contained. This is the principle of least privilege applied to network architecture.
